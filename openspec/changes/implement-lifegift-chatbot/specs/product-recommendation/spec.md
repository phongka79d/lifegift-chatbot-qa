## Purpose

Combine MySQL hard constraints with Qdrant semantic preferences to recommend products.

## ADDED Requirements

### Requirement: Hard constraints are never overridden by semantic ranking
The system SHALL first filter candidates with MySQL constraints and SHALL NOT allow a semantically similar product to re-enter the candidate set if it violates a budget, category, or availability constraint.

#### Scenario: Budget constraint preserved
- **WHEN** the user requests a product under 300,000 VND and a higher-priced product scores highly in vector retrieval
- **THEN** the higher-priced product SHALL NOT be returned

#### Scenario: Availability constraint preserved
- **WHEN** a zero-stock product scores highly in vector retrieval
- **THEN** the zero-stock product SHALL NOT be returned

### Requirement: Recommendation combines hard filters with semantic preferences
The system SHALL rank MySQL-filtered candidates using semantic preference matches and select a limited number of top candidates.

#### Scenario: Hybrid recommendation
- **WHEN** the user asks for aromatic low-bitterness coffee under 300,000 VND
- **THEN** the system returns candidates filtered by MySQL and ordered by semantic relevance, with an explanation generated by the LLM

### Requirement: Recommendation degrades safely without semantic retrieval
If semantic retrieval is unavailable, the system SHALL still return the MySQL-filtered candidates and clearly indicate that preference matching is limited.

#### Scenario: Semantic retrieval failure
- **WHEN** Qdrant retrieval fails during a recommendation
- **THEN** the system returns valid filtered candidates and marks preference matching as limited
